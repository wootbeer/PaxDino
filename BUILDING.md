# Building Guide

You need your own copy of the game: Turok: Rage Wars, USA (`NRWE`), see
docs/ROM_LAYOUT.md for the hashes. The ROM is never committed; the recompiled
code is generated from it locally.

## Windows quick start (Visual Studio)

Install Visual Studio 2022 with the "Desktop development with C++" workload,
including the "C++ Clang Compiler for Windows" and "C++ CMake tools for
Windows" components, plus Git for Windows. Then, in any PowerShell:

```powershell
git clone --recurse-submodules https://github.com/wootbeer/PaxDino.git
cd PaxDino
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\tools\setup-windows.ps1 -Rom "C:\path\to\Turok - Rage Wars (USA).n64"
```

`tools/setup-windows.ps1` does steps 1-5 below: it enters Visual Studio's
x64 build environment, fetches submodules, converts and checks the ROM,
generates `RecompiledFuncs/` with N64Recomp and builds
`build\PaxDino.exe`. Rerun it with `-Regenerate` after
changing `turokrw.us.toml` or the symbol file.

To work on it in Visual Studio afterwards:

1. **File > Open > Folder...** and pick the `PaxDino` folder. Visual
   Studio reads `CMakePresets.json` and configures by itself.
2. Pick **Windows x64 Release** in the configuration drop-down (also
   **RelWithDebInfo**, optimized with debug info, and **Debug**, which has a
   console window but runs slowly). `RecompiledFuncs/` is in the source
   folder, so every configuration uses the one the script generated.
3. Pick **PaxDino.exe** as the startup item, then build
   (Ctrl+Shift+B) and run or debug (F5).

The build copies `assets/` next to the exe, so it runs from the build
folder. Edits to `src/` only need a rebuild; changes to the TOML or symbols
need `setup-windows.ps1 -Regenerate` (N64Recomp isn't part of the build).

The rest of this guide is the same process step by step, and Linux.

## 1. Clone with submodules

```bash
git clone --recurse-submodules https://github.com/wootbeer/PaxDino.git
cd PaxDino
# if you forgot --recurse-submodules:
git submodule update --init --recursive
```

## 2. Install dependencies

The same as the [BattleTanx recomp](https://github.com/wootbeer/btgarecomp)
(its BUILDING.md has the details).

- **Windows:** Visual Studio 2022 with "Desktop development with C++",
  including "C++ Clang Compiler for Windows" and "C++ CMake tools for
  Windows".
- **Linux (Ubuntu/Debian):**
  `sudo apt-get install cmake ninja-build libsdl2-dev libgtk-3-dev libvulkan-dev lld llvm clang`

## 3. Put the ROM in place

Place your dump in the repo root, named exactly `turokrw.us.z64`, in
big-endian `.z64` order (header bytes `80 37 12 40`). To convert a `.n64`
or `.v64` dump:

```bash
python3 tools/normalize_rom.py "Turok - Rage Wars (USA).n64" turokrw.us.z64
```

The game asks for the ROM again on first launch (any of the three byte
orders) and checks it against XXH3-64 `0x21667bf153183fa0`.

## 4. Configure, then generate the recompiled code

Configuring applies the local fixes in `lib-patches/` to the submodules,
including the N64Recomp one this game needs, so configure first and build
N64Recomp from the same tree.

**Linux:**

```bash
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release -DCMAKE_C_COMPILER=clang -DCMAKE_CXX_COMPILER=clang++
cmake --build build --target N64RecompCLI
./build/N64ModernRuntime/librecomp/N64Recomp/N64Recomp turokrw.us.toml
cmake -S . -B build   # picks up the new RecompiledFuncs/*.c
```

**Windows** (in an x64 Developer PowerShell for VS 2022; see the BattleTanx
BUILDING.md troubleshooting section about x64 vs x86 shells and which
clang-cl):

```powershell
$env:TRW_CLANGCL = "C:\Program Files\Microsoft Visual Studio\2022\Community\VC\Tools\Llvm\x64\bin\clang-cl.exe"
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release -DCMAKE_C_COMPILER="$env:TRW_CLANGCL" -DCMAKE_CXX_COMPILER="$env:TRW_CLANGCL"
cmake --build build --target N64RecompCLI
.\build\N64ModernRuntime\librecomp\N64Recomp\N64Recomp.exe turokrw.us.toml
cmake -S . -B build
```

If the N64Recomp executable isn't at that path, look for `N64Recomp` /
`N64Recomp.exe` under `build/`.

`RecompiledFuncs/` is gitignored; regenerate it after any change to
`turokrw.us.toml` or the symbol file. The audio microcode (`rsp/`) is
generated by the main build.

## 5. Build and run

```bash
cmake --build build --target PaxDino
./build/PaxDino        # Windows: .\build\PaxDino.exe
```

The game loads `assets/` relative to the working directory; the build copies
it next to the exe, so run it from the build folder or the repo root.

## Release packages

- **Windows:** `.\tools\package-windows.ps1 -Version 0.1.1-beta` gives
  `dist\PaxDino-<version>-windows.zip`.
- **Linux / Steam Deck:** `tools/package-linux.sh 0.1.1-beta` gives
  `dist/PaxDino-<version>-linux.tar.gz` with an AppImage. It runs on systems
  with a glibc at least as new as the one it's built on, so build it on an
  older distro (or SteamOS's) for the widest reach.

Both use their own build folder, so a dev build is left alone.

## Regenerating the symbol file

Only needed when changing function boundaries or names:

```bash
python3 tools/find_functions.py turokrw.us.z64 syms/functions.txt \
    --glabels syms/spimdisasm_starts.txt \
    --extra syms/libultra.txt syms/libaudio_n64sym.txt syms/game_names.txt
python3 tools/make_syms_toml.py syms/functions.txt TurokRWSyms/turokrw.us.syms.toml
```

`find_functions.py` needs `rabbitizer` (`pip install rabbitizer`).
`syms/spimdisasm_starts.txt` came from splat (`tools/splat.yaml`); rerun
splat only to refresh it.
